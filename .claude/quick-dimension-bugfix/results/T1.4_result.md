## Findings

### 1. Ownership is consistent and local to one file
- Verified upstream T1.1 fact: both the cosmetic `actualSegmentCount` defect and the `valueSource` enhancement belong to `ArcTool.Core/Services/QuickDimensionReadOnlyXmlLogService.cs`.
- Current exact sites are still the ones called out by T1.1:
  - top-level `actualSegmentCount` derivation/write: `ArcTool.Core/Services/QuickDimensionReadOnlyXmlLogService.cs:507-543`
  - per-segment audit builder: `ArcTool.Core/Services/QuickDimensionReadOnlyXmlLogService.cs:665-699`
- No `valueSource` / `ValueSource` token exists anywhere under `ArcTool.Core` right now (workspace grep returned no matches), so the enhancement is new and remains local to this service.

### 2. `actualSegmentCount` is currently derived from the wrong source
- `BuildChainCreationAuditElement(...)` currently does all three of these from the raw Revit property path:
  - derives `reportedSegmentCount = dimension?.NumberOfSegments ?? 0` at `QuickDimensionReadOnlyXmlLogService.cs:507`
  - writes top-level `ChainCreationAudit/@actualSegmentCount` from that variable at `:526`
  - passes that same variable into `BuildSegmentsAuditElement(...)` at `:543`
- `BuildSegmentsAuditElement(...)` then writes nested `Segments/@actualSegmentCount` from its `reportedSegmentCount` parameter at `QuickDimensionReadOnlyXmlLogService.cs:665-699`, specifically `:668` and `:698`.
- Therefore there are exactly two emitted `actualSegmentCount` attributes that must stay aligned: the top-level audit attribute and the nested `Segments` attribute.

### 3. The measured-value count already exists; it is the normalized list count
- `ExtractSegmentValues(...)` is the normalization point for measured values: `QuickDimensionReadOnlyXmlLogService.cs:740-774`.
- The in-file summary comment explicitly documents the dual Revit shape:
  - single-segment dimension: `NumberOfSegments == 1`, `Segments` is empty, value lives on `Dimension.Value` (`QuickDimensionReadOnlyXmlLogService.cs:734-739`)
  - multi-segment dimension: `Segments` contains the per-segment values (`QuickDimensionReadOnlyXmlLogService.cs:734-739`)
- The implementation matches that comment:
  - multi-segment path reads `segment.Value` for each `DimensionSegment` at `QuickDimensionReadOnlyXmlLogService.cs:753-759`
  - single-segment path reads `dimension.Value` at `QuickDimensionReadOnlyXmlLogService.cs:762-766`
- So the measured segment count is already available as `segmentValuesInternal.Count` after extraction at `QuickDimensionReadOnlyXmlLogService.cs:510`. That is the correct future source for both `actualSegmentCount` attributes.
- Revit API basis:
  - [`Dimension` class](https://www.revitapidocs.com/2026/210f88be-e3c5-26a4-7dd8-3296f6725cce.htm) documents `NumberOfSegments`, `Segments`, and `Value`
  - [`Dimension.Segments`](https://www.revitapidocs.com/2026/d7fcdab2-ca81-0ed1-4813-f7aa092430d7.htm) returns the `DimensionSegmentArray`
  - [`DimensionSegment` class](https://www.revitapidocs.com/2026/36b254a0-3dc5-7bdc-d6b4-986e5d82ddbf.htm) documents `Value`
  - [`DimensionSegmentArray.Size`](https://www.revitapidocs.com/2026/3aa3ea05-474f-f2d6-f8c9-dc821fcfc782.htm) is only the raw array count, not the normalized measurement count

### 5. What `valueSource` must mean
- The attribute must distinguish the two already-documented extraction paths in this file, nothing more:
  - single-segment normalized value came from `Dimension.Value` (`QuickDimensionReadOnlyXmlLogService.cs:762-766`)
  - multi-segment normalized value came from `DimensionSegment.Value` (`QuickDimensionReadOnlyXmlLogService.cs:753-759`)
- This enhancement belongs at the segment-entry emission point inside `BuildSegmentsAuditElement(...)` because that is where each `<Segment>` XML node is constructed (`QuickDimensionReadOnlyXmlLogService.cs:686-692`).
- `segmentArraySize` set later at `QuickDimensionReadOnlyXmlLogService.cs:545` remains a separate raw diagnostic and must not be repurposed as `actualSegmentCount`.

## Decision
The audit/logging fix boundary is fully locked: T5.2 and T5.3 should edit only `ArcTool.Core/Services/QuickDimensionReadOnlyXmlLogService.cs`, changing both emitted `actualSegmentCount` attributes to use the normalized measured-value count and adding per-segment `valueSource` at the XML segment-construction site, while leaving strict `Exact` / full `Reversed` semantics, owner matching, segment-value matching, and the 0.1 mm tolerance untouched.
