No blocking contradiction found. Three benign divergences were recorded and must be carried forward as working notes rather than remediation items:

2. **`AddOpeningReferenceInfo` has three branches, not one.** The contract's §5 excerpt shows only the `familyReference != null` branch. T1.2 pins that branch at `:593-599`; T1.3 additionally identifies a fallback-preferred branch at `:583-590` (guarded by `fallbackEnabled && useFallbackReference && fallbackReference != null && fallbackPoint != null`, and it returns early) and a fallback-only branch at `:603-609`. Consistent, but it means the BUG-11 station-derivation change lands on the family branch while BUG-10 metadata normalization concerns the two `HostWallOpeningGeometry` branches, and the fallback-preferred branch can preempt the family branch entirely for a given side.
3. **Audit assembly block span.** Contract says `~498-543`; T1.1 reports the enclosing method as `453-547` with derivation at `:507` and writes at `:526` / `:698`. Same defect sites, wider enclosing method. No conflict.

### 3) Residual uncertainty and why it does not force NO_GO

T1.2 is the only PASS carrying open questions: it is not documented in the 2026 API reference that a `Reference` from `GetReferences(Left/Right)` always resolves through `Element.GetGeometryObjectFromReference` to geometry from which a world-space point/station can be read, nor which object path applies when the resolved geometry is neither `Face` nor `Edge`.

This is an unresolved **mechanism** question, not an unresolved **invariant** or **ownership** question, and Phase 2 exists precisely to answer it: Phase 2 is diagnostic instrumentation on fixture 379469 (T2.1–T2.2 analysis, T2.3 collector instrumentation, T2.4 build, T2.5 operator runbook), and the fix itself is deferred to Phase 4 behind Phase 3 evidence analysis. Entering Phase 2 with this question open is the intended sequence; entering Phase 4 with it open would not be. T1.2 also already forbids the unsafe resolution (silently reusing `fallbackPoint` / `estimatedPoint` / label order), so the risk of an unsafe downstream edit is closed by rule, not left to judgment.

Two further safety properties hold for Phase 2 specifically:
- The only Phase 2 source edit is a collector instrumentation change on a serialized write lane already owned exclusively by T2.3.
- Diagnostic tiers must go into a separate field/model; `QuickDimensionReferenceStrategy` values must not be extended (contract §4). This keeps Phase 2 instrumentation from mutating the audited contract surface.

### 4) Risks to carry into Phase 2

- Instrumentation must be additive and read-only in effect: no change to candidate ordering, station values, reference selection, dedupe, or audit gate semantics, so that smoke #1–#4 geometry stays comparable.
- Diagnostic output must land in the same combined XML (one XML per run) so operator evidence stays single-artifact per run.
- Flip/mirror/orientation remains an unproven hypothesis. Phase 2 instrumentation should capture those flags as data, not assume them as cause.
- Fixture 379469 is the diagnostic fixture of record because it contains both swapped (Window 379475, Doors 379472/379471) and ordered (Window 379484, same family/type) instances.
