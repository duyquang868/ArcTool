## Findings

### 1) BUG-11 defect site confirmation

The cross-association defect lives at `AddOpeningReferenceInfo:593-599` (family branch):

```csharp
if (familyReference != null)
{
    referenceInfos.Add(new OpeningReferenceInfo(
        familyReference,                 // named Reference from GetReferences(Left/Right)[0]
        fallbackPoint ?? estimatedPoint, // physical point derived INDEPENDENTLY
        label,
        QuickDimensionReferenceStrategy.FamilyInstanceLeftRight));
    return;
}
```

The named `familyReference` comes from `TryGetFamilyInstanceReferences:658-690`, which returns `GetReferences(Left)[0]` and `GetReferences(Right)[0]` with no geometry resolution. The `fallbackPoint ?? estimatedPoint` path is:
- `fallbackPoint`: from `TryGetHostWallOpeningReferences:692-823` (host wall solid edge scan)
- `estimatedPoint`: from `TryGetEstimatedReferencePoints:944-982` (bbox extremum)

Neither path resolves the named `familyReference` to its own geometry. The pairing happens by semantic label (`"Left"` / `"Right"`) at the call site in `TryProjectOpeningOntoWallAxis:546-552`.

### 2) Evidence requirement for Phase 2

To prove whether BUG-11 is caused by this cross-association or by a deeper reference-geometry mismatch, the instrumentation must log, per opening side:

- **Reference identity** — stable string or owner ElementId
- **Point used for projection** — the exact XYZ handed to `TryProjectPointToPickedSpan`
- **Projected station** — the `parameterOnDimensionLine` result
- **Point provenance** — whether the point came from:
  - the named reference's own resolved geometry (reference-atomic),
  - `fallbackPoint` from host wall edge scan (independent),
  - `estimatedPoint` from bbox extremum (independent)
- **Chosen strategy** — already logged via `QuickDimensionReferenceStrategy`

The collector must distinguish "reference-owned" from "proxy-derived" provenance without inventing a geometry-resolution path that does not exist in the current code.

### 3) Current diagnostic flow

`TryProjectOpeningOntoWallAxis` already logs accepted candidates via the final `QuickDimensionCandidate` constructor at `:280-285`, and `AddAcceptedDiagnostics:1158-1172` emits Info-level diagnostics that include `SourceType`, `DisplayName`, `ParameterOnDimensionLine`, `ReferenceStrategy`, and `HostElementValue`.

The missing evidence is:
- the **point** used for projection (currently not logged),
- the **provenance** flag distinguishing reference-owned vs proxy-derived.

### 4) Minimal instrumentation design

**Logging point:** One new diagnostic emit inside the `foreach (OpeningReferenceInfo referenceInfo in referenceInfos)` loop at `TryProjectOpeningOntoWallAxis:265-287`, immediately after the successful `TryProjectPointToPickedSpan` call and before the `QuickDimensionCandidate` constructor.

**New diagnostic severity:** Use `QuickDimensionDiagnosticSeverity.Info` to match the existing accepted-candidate pattern, or introduce a new severity level `Debug` if the XML log service already supports it. Check the contract model before finalizing.

**Per-side evidence payload:**

```text
[PHASE2_INSTRUMENTATION] {displayName} [{referenceInfo.Label}]:
  Reference: {stableReferenceString or "null"}
  ReferenceOwner: {referenceInfo.Reference?.ElementId.Value ?? instance.Id.Value}
  ProjectionPoint: ({referenceInfo.ReferencePoint.X:F6}, {referenceInfo.ReferencePoint.Y:F6}, {referenceInfo.ReferencePoint.Z:F6})
  ProjectedStation: {parameterOnDimensionLine:F6}
  PointProvenance: {DeriveProvenance(referenceInfo, fallbackReferences, estimatedLeftPoint, estimatedRightPoint, referenceInfo.Label)}
  Strategy: {referenceInfo.ReferenceStrategy}
```

**Provenance derivation logic** (new helper method in the same file):

```csharp
private static string DeriveProvenance(
    OpeningReferenceInfo referenceInfo,
    OpeningReferencePair fallbackReferences,
    XYZ estimatedLeftPoint,
    XYZ estimatedRightPoint,
    string label)
{
    // If the strategy is HostWallOpeningGeometry, the point is reference-owned (edge scan resolved that reference).
    if (referenceInfo.ReferenceStrategy == QuickDimensionReferenceStrategy.HostWallOpeningGeometry)
        return "Reference-Owned (HostWallOpeningGeometry)";

    // If the strategy is FamilyInstanceLeftRight, the point is proxy-derived because AddOpeningReferenceInfo:594
    // paired the named reference with fallbackPoint ?? estimatedPoint.
    // Distinguish which proxy source was used by pointer equality.
    if (referenceInfo.ReferenceStrategy == QuickDimensionReferenceStrategy.FamilyInstanceLeftRight)
    {
        if (label == "Left")
        {
            if (referenceInfo.ReferencePoint == fallbackReferences.LeftPoint)
                return "Proxy-Derived (Fallback Host Wall Left Edge)";
            if (referenceInfo.ReferencePoint == estimatedLeftPoint)
                return "Proxy-Derived (Estimated BBox Left Extremum)";
        }
        else if (label == "Right")
        {
            if (referenceInfo.ReferencePoint == fallbackReferences.RightPoint)
                return "Proxy-Derived (Fallback Host Wall Right Edge)";
            if (referenceInfo.ReferencePoint == estimatedRightPoint)
                return "Proxy-Derived (Estimated BBox Right Extremum)";
        }
        return "Proxy-Derived (Unknown Source)";
    }

    return "Unknown Strategy";
}
```

**Stable reference string:** Use `referenceInfo.Reference?.ConvertToStableRepresentation(doc)` if the collector has access to `Document`; otherwise log `referenceInfo.Reference?.ElementId.Value.ToString()` as a proxy.

### 5) Scope boundaries respected

- **No geometry resolution added:** The instrumentation does not call `Element.GetGeometryObjectFromReference` or any 2026 API that would attempt to derive a point from the named reference's own geometry. It only logs the point that the current code already uses.
- **No production logic change:** The `QuickDimensionCandidate` constructor call stays unchanged. The diagnostic emit is additive and read-only.
- **No audit semantics widening:** The instrumentation does not touch `QuickDimensionChainCreationService.cs`, `QuickDimensionReadOnlyXmlLogService.cs`, or any audit gate logic.
- **Localized to one file:** All changes stay inside `QuickDimensionDoorWindowCandidateCollector.cs`.

### 6) Output sink confirmation

The existing diagnostic flow emits `QuickDimensionDiagnostic` objects into the `diagnostics` list, which is passed to `BuildResult:1091-1128` and then logged by the XML log service. The new Phase 2 diagnostic must use the same `diagnostics.Add(...)` pattern and will automatically appear in the combined XML output.

Severity levels available in the contract model must be verified from `QuickDimensionContract.cs` before finalizing the diagnostic severity. If `Debug` does not exist, use `Info` and prefix the message with `[PHASE2_INSTRUMENTATION]` for easy filtering.

### 7) Instrumentation insertion point

Insert the new diagnostic emit at `TryProjectOpeningOntoWallAxis:272` (immediately after the successful `TryProjectPointToPickedSpan` call and before the `candidates.Add(new QuickDimensionCandidate(...))` call at `:280`).

The emit must occur inside the `foreach (OpeningReferenceInfo referenceInfo in referenceInfos)` loop so that each accepted opening side logs its own evidence. Rejected sides (those that fail `TryProjectPointToPickedSpan`) already have their own diagnostic emit at `:273-277` and do not need Phase 2 instrumentation.

## Decision

The minimal instrumentation is one new helper method `DeriveProvenance` and one new `diagnostics.Add(...)` call inside the accepted-reference loop at `TryProjectOpeningOntoWallAxis:272`. The diagnostic payload logs reference identity, projection point, projected station, point provenance, and strategy. Point provenance distinguishes reference-owned (HostWallOpeningGeometry) from proxy-derived (fallback edge or estimated extremum) by comparing pointer identity with the known proxy sources. The instrumentation does not add geometry resolution, does not change production candidate construction, and stays localized to the BUG-11 owner file.
