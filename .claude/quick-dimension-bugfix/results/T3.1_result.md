### What EV-1 proves

1. Every diagnostic opening listed here used `Strategy=FamilyInstanceLeftRight` but logged `PointProvenance=Proxy-Derived (Fallback Host Wall Left/Right Edge)`.
2. Therefore the projected station in EV-1 is not evidenced as coming from the same geometry object that supplies the named stable reference identity; the station is evidenced as coming from a proxy/fallback host-wall edge source.
3. The same proxy-derived pattern appears on both swapped instances (379475, 379472, 379471) and the ordered instance (379484). So proxy-derived provenance is sufficient to show non-atomic identity/station association, but not sufficient by itself to predict whether a given instance will swap.
4. EV-1 also says `ownerEqualToExpected=true` for all created references listed above, so the excerpt points to identity/station association as the defect signal for these openings, not a per-opening live-owner corruption in the committed reference rows shown.

### Missing fields / excerpt limits that reduce certainty

- The forwarded EV-1 excerpt omits `ProjectionPoint`, even though T2.5 expected that field in the XML instrumentation. Without the actual point, T3.2 can verify proxy provenance and station scalar, but cannot re-check the exact geometric point used for projection from the excerpt alone.
- The excerpt gives only stable suffixes (`...:0:SURFACE`, `...:2:SURFACE`), not full stable representations, which is enough to distinguish pair members but not enough to compare the full stable strings end-to-end.
- The excerpt does not include per-instance flip/mirror/orientation flags, so it cannot test the leading orientation hypothesis.
- The excerpt does not reconcile why run-level `referenceOwnersMatched=false` while every listed created opening reference says `ownerEqualToExpected=true`; the missing per-index owner breakdown keeps that aggregate false gate unexplained here.
