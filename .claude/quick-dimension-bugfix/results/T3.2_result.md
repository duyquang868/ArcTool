This is the key sharpening beyond a generic BUG-11 restatement:

1. The same family/type can be swapped on one instance and ordered on another.
2. The same named-reference strategy can be swapped on one instance and ordered on another.
3. The same proxy-derived left/right provenance can be swapped on one instance and ordered on another.
4. The same expected stable suffix pattern (`0` for Left, `2` for Right) can still lead to opposite committed outcomes.

Therefore none of the currently logged collector fields provide a safe discriminator for “this instance needs swapping” versus “this instance is already correct”. The ordered case (`379484`) is not evidence that label-based pairing is valid; it is evidence that the current non-atomic pairing can coincidentally align on some instances.

That narrows the production rule to an unconditional one: every named reference must carry its own measured wall-axis station, even when the current proxy-derived pair happens to commit in the expected order.

### 2. What invariant actually distinguishes swapped vs ordered cases here

The evidence does **not** reveal a positive per-instance property that separates `379475` from `379484`; the excerpt omits flip/mirror/orientation and the actual projected geometry points (`T3.1_result.md:62-67`).

What the comparison does isolate is a stronger negative invariant:

- Under the current instrumentation, swapped and ordered same-type instances are observationally indistinguishable **before commit** on all logged collector-side fields that EV-1 exposes.
- The only visible difference is the committed order itself.

That means the current algorithm is missing the discriminating datum. Per the shared contract, the missing datum must be the station derived from the geometry of the specific named reference itself, not a proxy point paired by label (`01_SHARED_CONTRACT.md:32-37`, `01_SHARED_CONTRACT.md:117-142`).

So the invariant that matters for the fix is not “swapped instances have property X”; it is “current logged properties are insufficient because identity and station are not bound atomically”. This supports an unconditional production correction rather than a heuristic branch.

Limit: EV-1 does not include an ordered door control, so doors broaden scope but do not provide the same same-type swapped-vs-ordered contrast that windows `379475` and `379484` provide.

### 4. Production-readiness of the reference-owned station hypothesis

The evidence supports the reference-owned station hypothesis strongly enough for production, for these reasons:

- Same family/type, same strategy, same logged provenance, different committed outcomes means no label-only or family/type-only rule can be trusted.
- All observed openings still have `ownerEqualToExpected=true`, so the defect signal is not “wrong live reference owner”; it is the association between correct reference identity and independently-derived station.
- Ordered instance `379484` proves that current behavior can look correct by coincidence, which makes heuristic “swap only known bad cases” logic unsafe.
- Door corroboration shows the issue is not isolated to one family class or one opening kind.

That is strong enough to justify the production fix shape mandated by the contract: derive the projected station from each named reference’s own geometry and bind identity + station atomically. It is **not** strong enough to justify any narrower heuristic, such as conditioning on family, type, shell, or presumed orientation.

### 5. What EV-1 does not prove

The task specifically warned against overstating orientation evidence. That caution remains necessary.

Not proven by EV-1:
- flip state as the cause
- mirror state as the cause
- orientation/handing as the cause
- a predictable local-pair rule that could safely pre-classify instances

Those remain hypotheses only because the excerpt does not contain those instance flags or equivalent geometry-state evidence (`T3.1_result.md:66`).
