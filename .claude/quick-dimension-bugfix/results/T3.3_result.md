## Findings

### 1. Exact implementation rule
Evidence now supports only one production rule for BUG-11:
- In `QuickDimensionDoorWindowCandidateCollector`, every candidate created from `FamilyInstanceReferenceType.Left/Right` must carry a wall-axis station derived from that same `Reference`'s own geometry.
- The collector must bind `Reference` identity and projected station atomically at candidate creation time.
- The `"Left"` / `"Right"` label may still identify which reference was requested, but it must not choose or imply the station. This is the shared invariant and is sharpened by the same-type control in wall `379469` (`01_SHARED_CONTRACT.md:35-39`, `T3.2_result.md:31-40`, `T3.2_result.md:96-109`).

Why this is now final:
- Window `379475` and window `379484` are the same family/type: `M_Fixed - 0406 x 0610mm`.
- Both logged the same visible collector-side pattern before commit: `Strategy=FamilyInstanceLeftRight`; `[Left] PointProvenance=Proxy-Derived (Fallback Host Wall Left Edge)`; `[Right] PointProvenance=Proxy-Derived (Fallback Host Wall Right Edge)`.
- Their committed order still diverged: `379475` swapped, `379484` stayed ordered.
- Therefore no production fix that still pairs named references with proxy-derived left/right points can be trusted, even when it appears to work on an ordered instance (`T3.2_result.md:21-40`, `T3.2_result.md:75-82`).

### 2. Edit-ready bypass/removal rule
The current named-reference defect site is the association below:

```csharp
familyReference + (fallbackPoint ?? estimatedPoint)
```

That association must be removed or bypassed whenever `familyReference != null` (`01_SHARED_CONTRACT.md:117-133`).

Required narrow replacement rule inside the collector owner file:
1. Keep named-reference selection unchanged: `GetReferences(Left)[0]` and `GetReferences(Right)[0]` remain the source of named references (`01_SHARED_CONTRACT.md:38-39`, `01_SHARED_CONTRACT.md:86-91`).
2. For each non-null named reference, resolve that reference's own physical point/projection on the selected wall axis.
3. Create `OpeningReferenceInfo` from that exact `Reference` plus that exact per-reference point.
4. Do not pass `fallbackPoint`, `estimatedPoint`, or any other label-keyed proxy point into `OpeningReferenceInfo` for the `FamilyInstanceLeftRight` path.
5. The existing `HostWallOpeningGeometry` fallback path remains the only place where host-wall-edge/proxy-derived points are allowed, and only when the collector is already using fallback because named references are unavailable (`01_SHARED_CONTRACT.md:40-45`, `01_SHARED_CONTRACT.md:87-92`).

In short:
- Forbidden: `named reference -> proxy-derived Left/Right point`
- Required: `named reference -> point/station derived from that same named reference`

### 3. Scope guard
This rule is intentionally narrow enough for the collector owner file:
- change only the named-reference station derivation/association path;
- do not change fallback reference-pair selection;
- do not change strategy enums;
- do not change audit acceptance semantics;
- do not add family/type/shell/orientation heuristics (`01_SHARED_CONTRACT.md:32-45`, `T3.2_result.md:77-82`, `T3.2_result.md:108-110`).

### 4. Residual uncertainty that does not block implementation
Non-blocking unknowns remain:
- flip/mirror/orientation may explain why some instances swap and others do not, but EV-1 does not prove any one factor (`01_SHARED_CONTRACT.md:141-142`, `T3.2_result.md:84-95`);
- the exact helper shape used to extract a geometric point from a named reference is still an implementation choice, but any valid implementation must satisfy the ownership invariant above and must not fall back to label-proxy pairing for named references.

No new Revit API claim is introduced here; this result only fixes the collector invariant already mandated by the contract.
