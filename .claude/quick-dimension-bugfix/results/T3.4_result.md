## Findings

### 1. The gate question is now narrow and answerable
The task asks for a production start gate, not a root-cause theory for why specific instances swap. Per task definition, `PASS` requires one clear production rule; `NO_GO` applies only if multiple materially different fixes still fit the evidence; `BLOCKED` applies only if operator evidence is insufficient (`T3.4_bug11_go_no_go_gate.md:13-24`).

The shared contract already fixes the required shape of a valid BUG-11 correction:
- derive each named `FamilyInstanceReferenceType.Left/Right` station from that same reference's own geometry;
- bind identity + station atomically;
- do not infer station from the `Left` / `Right` label;
- keep `GetReferences(Left)[0]` / `GetReferences(Right)[0]` unchanged;
- do not whitelist local pair swaps (`01_SHARED_CONTRACT.md:32-39`).

So the remaining gate is whether T3.1-T3.3 plus EV-1 reduce the evidence to exactly that one production rule.

### 2. T3.1 proves the current collector path is non-atomic
T3.1 extracted the decisive pattern from EV-1 for wall `379469`:
- named family references were selected for windows `379475`, `379484` and doors `379472`, `379471`;
- the logged station/provenance for every one of those named references was still proxy-derived from fallback host-wall edges;
- committed order then swapped on `379475`, `379472`, `379471`, but stayed ordered on `379484` (`T3.1_result.md:17-29`, `T3.1_result.md:45-60`).

That establishes the defect class needed for the gate:
- the collector is pairing a correct named reference identity with a station not evidenced as coming from that same geometry object;
- the current path is therefore non-atomic on identity vs station.

This is enough to rule out any claim that the existing `familyReference + proxy point` association is already safe.

### 3. T3.2 eliminates the plausible heuristic branches
T3.2 is the decisive ambiguity-killer because it compares same-type windows inside the same wall fixture:
- swapped window: `379475`
- ordered window: `379484`
- both family/type: `M_Fixed - 0406 x 0610mm`
- both strategy: `FamilyInstanceLeftRight`
- both visible provenance: proxy-derived fallback host-wall left/right edge
- both expected stable suffix pattern: `Left -> ...:0:SURFACE`, `Right -> ...:2:SURFACE`
- opposite committed outcomes (`T3.2_result.md:12-40`).

That removes the materially different fix branches that would have forced `NO_GO`:
- not a family-specific fix;
- not a type-specific fix;
- not a shell-specific fix;
- not a generic `FamilyInstanceLeftRight` label-only fix;
- not a safe "swap known bad cases" rule;
- not a rule keyed only on the currently logged proxy provenance.

T3.2 states the strong negative invariant clearly: under current logging, swapped and ordered same-type instances are observationally indistinguishable before commit on all exposed collector-side fields except the final committed order (`T3.2_result.md:42-53`). Therefore the current algorithm is missing the discriminating datum, and that missing datum must be the station owned by the same named reference geometry (`T3.2_result.md:48-53`, `T3.2_result.md:75-83`).

This is the point where `NO_GO` stops being justified: the evidence no longer supports multiple materially different production fixes.

### 4. T3.3 converts that evidence into one edit-ready production rule
T3.3 finalized the only surviving rule:
- whenever `familyReference != null`, bypass/remove `familyReference + (fallbackPoint ?? estimatedPoint)`;
- for each non-null named reference, resolve the wall-axis point/station from that exact reference's own geometry;
- create `OpeningReferenceInfo` from that exact reference plus that exact per-reference point;
- keep the existing fallback path only for cases where named references are unavailable (`T3.3_result.md:10-40`, `T3.3_result.md:57-69`).

This matters for the gate because it distinguishes:
- one production rule, which is now fixed; from
- several possible helper implementations, which are not materially different fixes.

A different helper shape for obtaining the point from the named reference is still an implementation detail, not a competing production rule, as long as it preserves the invariant above (`T3.3_result.md:50-55`). That residual choice does not justify `NO_GO`.

### 5. Why this is PASS, not NO_GO
`NO_GO` would require two or more materially different fixes that still fit the evidence. After T3.3, that is no longer true.

The evidence-and-contract bundle now rules out all alternative fix classes that would change behavior differently:
- Local-pair swap acceptance is forbidden and contradicted by the contract (`01_SHARED_CONTRACT.md:32-34`).
- Re-indexing or relabeling by unordered sets would change audit semantics and is forbidden (`01_SHARED_CONTRACT.md:32-34`).
- Changing `GetReferences(Left)[0]` / `GetReferences(Right)[0]` selection is forbidden and unsupported by evidence (`01_SHARED_CONTRACT.md:38-39`).
- Changing fallback pair selection or attachment behavior would widen scope beyond BUG-11 and violate the contract (`01_SHARED_CONTRACT.md:40-45`).
- Conditional heuristics keyed on family/type/shell/orientation remain unsupported because the ordered control `379484` and swapped control `379475` are same-type and same visible strategy/provenance (`T3.2_result.md:21-40`, `T3.2_result.md:84-95`).

What remains is one clear production rule with narrow scope.

### 6. Why this is PASS, not BLOCKED
`BLOCKED` would require insufficient operator evidence. That is also no longer true.

The available evidence already covers:
- two committed runs for wall `379469` with created dimension ids `384983` and `384984`;
- swapped windows and doors under the named-reference path;
- an ordered same-type window control under the same visible collector-side pattern;
- confirmation that live owners are not the distinguishing signal here (`T3.1_result.md:57-60`, `T3.2_result.md:75-82`).

That is sufficient to decide the production rule. Additional evidence such as flip/mirror/orientation flags could explain *why* individual instances diverged, but T3.2/T3.3 already show those unknowns are non-blocking for the fix shape (`T3.2_result.md:84-95`, `T3.3_result.md:50-55`).

## Decision
PASS. Phase 4 may start safely because the evidence now supports exactly one production BUG-11 rule: in `QuickDimensionDoorWindowCandidateCollector`, every named `FamilyInstanceLeftRight` reference must carry a wall-axis station derived from that same reference's own geometry, with identity and station bound atomically; the current `familyReference + (fallbackPoint ?? estimatedPoint)` pairing must be bypassed whenever `familyReference != null`, while named-reference selection and the existing non-named fallback path remain unchanged.
