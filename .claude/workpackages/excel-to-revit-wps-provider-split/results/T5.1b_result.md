## Findings
- EV-1 confirmed the failure shape on the current WPS build: `Workbooks.Open` on `KET.Application` failed with `DISP_E_TYPEMISMATCH` when called with only one positional argument (`.claude/workpackages/excel-to-revit-wps-provider-split/evidence/EV-1_output.txt:76-89`).
- The official Excel object-model signature for `Workbooks.Open` is variadic with optional trailing parameters: `Open(FileName, UpdateLinks, ReadOnly, Format, Password, ...)`, so a late-bound callee that rejects the single-argument form can plausibly require one or more explicit optional placeholders instead of omitted trailing arguments. Source: Microsoft Learn, Workbooks.Open method (Excel), `https://learn.microsoft.com/en-us/office/vba/api/Excel.Workbooks.Open`.
- The WPS provider now routes workbook opening through a dedicated helper rather than a single direct call. Implemented call order in `D:\Quang mini\OneDrive - MSFT\Plugin Revit\ArcTool\ArcTool.Core\Services\Excel\WpsWorkbookPdfExporter.cs:77-110,187-190`:
  1. `Open(filePath)` — preserves the original shape first, exactly as required.
  2. `Open(filePath, Type.Missing)` — smallest optional-argument fallback; covers builds that insist on an explicit second COM slot.
  3. `Open(filePath, Type.Missing, Type.Missing)` — next compact extension; covers builds that expect both `UpdateLinks` and `ReadOnly` slots.
  4. `Open(filePath, Type.Missing, Type.Missing, Type.Missing, Type.Missing)` — reaches through `Format` and `Password` without brute-forcing the full 15-argument Excel signature.
- Rationale for the exact four shapes:
  - Attempt 1 is the known current implementation and preserves existing behavior where it already works.
  - Attempt 2 is the minimum explicit-optional fallback.
  - Attempt 3 covers the common early optional block (`UpdateLinks`, `ReadOnly`) with no speculative wider matrix.
  - Attempt 4 extends only far enough to cover the next two documented optional positions (`Format`, `Password`) because EV-1 showed a type mismatch at bind time, not a downstream file-open failure.
- Failure handling remains unchanged at the contract level: the helper logs one concise debug line per failed attempt, stops on the first non-null workbook, and returns `null` only when all shapes fail; the caller still emits `EngineFoundOpenFailed` and returns `false` without throwing (`WpsWorkbookPdfExporter.cs:87-110,187-190`).
