## What to decide

1. **ProgID probe order and rationale.** The user-directed chain is
   `KET.Application` → `ET.Application` → `Kingsoft.ET.Application`. `KET.Application` is the only one
   confirmed to resolve on any machine so far, so it stays first; the other two stay in the chain for
   other WPS builds but are unverified everywhere. Decide whether to append further
   candidates (for example `Kingsoft.ET`, `ET.Sheet.8`), and justify each addition or the decision not
   to add any. Account for per-user-only (HKCU) registration: detection must not assume a machine-wide
   COM registration exists. State the probe mechanism exactly:
   `Type.GetTypeFromProgID(progId, throwOnError: false)` → null check →
   `Activator.CreateInstance(type)`. Record what happens when the type resolves but instantiation
   throws (a stale registration is a real, reported failure mode).

2. **`InvokeMember` shapes.** For every operation in the locked session interface, give the exact
   late-bound call: target object, member name, `BindingFlags` combination, and argument array.
   Cover at minimum:
   - set `Visible = false`, set `DisplayAlerts = false` (`SetProperty`)
   - get `Workbooks`, call `Open(path)` (`InvokeMethod`)
   - get `Worksheets`, get `Count`, get `Item[i]` / `Item[name]`, get `Name`
   - get `Names` (workbook scope) and, if applicable, worksheet scope; get `Name.Name`,
     `Name.RefersToRange`, `Range.Worksheet`, `Worksheet.Name`
   - get `Range[address]`, get `UsedRange`, get `Range.Address` — note that `Address[false,false]` is a
     **parameterized property**, which is the single most error-prone late-bound call in this file.
     Specify precisely how to invoke it, and specify the fallback if the parameterized form fails.
   - get `PageSetup`; set `PrintArea`, `Zoom`, `FitToPagesWide`, `FitToPagesTall`, `TopMargin`,
     `BottomMargin`, `LeftMargin`, `RightMargin`, `PaperSize`
   - call `ExportAsFixedFormat` with the positional argument list used today
     (`ExcelInteropService.cs:220-228`)
   - call `Workbook.Close(false)`, call `Application.Quit`

   For each call, state whether a `MissingMemberException` / `COMException` there is **fatal** (abort
   the export) or **tolerable** (skip and continue, as the current code does for `PaperSize`).

3. **Constant table.** Replace every `Xl*` enum with a named `const` and a numeric literal. Minimum
   set: `xlTypePDF`, `xlQualityStandard`, `xlPaperEsheet`, `xlPaperA3`. Give each row: constant name to
   use in code, numeric value, source citation. Anything you cannot source gets `UNSOURCED` plus a
   recommendation (for example: skip that setting entirely rather than send a guessed number, since a
   wrong `PaperSize` value silently corrupts layout).

4. **Failure semantics.** Define what the WPS provider does when: no ProgID resolves; instantiation
   throws; `Workbooks.Open` throws; a sheet name is not found; `ExportAsFixedFormat` is missing; the
   expected PDF file does not exist after the call returns. Map each onto the session shape locked in
   `T1.1` so `T3.3`'s coordinator can distinguish "engine absent" from "engine present but export
   failed" — those two need different user-facing messages.

5. **COM release discipline for late-bound objects.** Every intermediate object returned by
   `InvokeMember` is a separate RCW that leaks if dropped. State the release rule and the
   `Dispose` order, mirroring the MS rule (child → parent, workbook → app), and note the risk of
   long-chained expressions that create untracked intermediates.

## Acceptance condition

The result file contains: a ProgID list with rationale, a call-shape table with one row per operation

`UNSOURCED`, an enumerated failure-semantics list, and the release rule. No claim about WPS behavior is
stated as verified — every one is either cited or flagged as an assumption to be tested by `EV-1`.
