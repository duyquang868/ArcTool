## Objective

Write the single entry point the rest of ArcTool uses. It auto-detects the engine (MS Excel first),
owns the temp-PDF lifetime, and hands the PDF to `PdfRasterImageService`. This is the **only** file
allowed to know that two providers exist.

## What to implement

1. **Public surface, shaped to the three existing call sites** so `T3.5`/`T3.6` are near-mechanical
   rewires. The old type was `IDisposable` and was used with `using`, exposing `OpenFile`,
   `GetSheetNames`, `GetNamedRanges`, `ExportRegion(sheet, region, outputPng)`. Keep that shape unless
   you have a concrete reason to change it — a divergence multiplies the risk in `T3.5`/`T3.6`. State
   the final surface explicitly in your result file; those two tasks code against it.

2. **Engine auto-detection, MS first (R10).**
   - Probe MS Excel first. If it resolves, use `MsExcelWorkbookPdfExporter`.
   - Otherwise probe the WPS ProgID chain from `T1.2`. If one resolves, use `WpsWorkbookPdfExporter`.
   - If neither resolves, fail with a message that names both engines, so a WPS user is not told
     "Excel is missing" when their real problem is a broken WPS COM registration.
   - Detection must not launch an application as a side effect of probing where avoidable. Prefer
     `Type.GetTypeFromProgID(progId, false) != null` over instantiating. If you must instantiate to
     detect, say so and explain why.
   - Cache the detection result per instance, not process-wide statics that would survive an install
     change mid-session.

3. **Three distinguishable failure modes** (from `T1.2` §4), each with its own message:
   no engine installed; engine present but workbook open failed; engine present and open succeeded but
   export failed. `ExcelSyncEngine.cs:162` and `:171` already build user-facing messages — keep those
   observable outcomes intact and let your messages add engine context, not replace them.

4. **Temp-PDF ownership is yours.** Create it as
   `Path.Combine(Path.GetTempPath(), $"ArcTool_ExcelSync_{Guid.NewGuid():N}.pdf")` — same pattern as the
   old code at `ExcelInteropService.cs:218-219` — pass it to the provider, hand it to
   `PdfRasterImageService`, then delete it in a `finally` that cannot throw. This replaces the old
   `finally` at line 357. Deleting the temp PDF must never mask a real export failure.

5. **Dispose** must dispose the underlying provider session exactly once, and be safe to call twice.

## Constraints

- Only this one file. `ArcTool.Core.csproj` needs no change — if you think it does, return `BLOCKED`.
- Do not touch either provider, the interface, the raster service, `ExcelInteropService.cs`,
  `ExcelSyncEngine.cs`, or the window.
