# T4.1 — MS Excel behavior-parity review against contract R11

- depends on: `T3.7` (`PASS`)
- write_scope: result only → `results/T4.1_result.md`

## Objective

Prove, by reading code rather than by running it, that a machine with MS Excel behaves exactly as before
the refactor. This is the review that protects the working majority of users from a change made for the
minority who have only WPS.

## Inputs you may read

- `01_SHARED_CONTRACT.md` (this package), especially R11 and §4
- `ArcTool.Core/Services/_backup/ExcelInteropService.cs.bak` — the pre-refactor original, your left-hand
  column. This is the reason the backup was required.
- The five new files under `ArcTool.Core/Services/Excel/`
- `ArcTool.Core/Services/ExcelSyncEngine.cs` — lines 140-200 only
- `ArcTool.Core/UI/ExcelToRevitWindow.xaml.cs` — lines 380-519 only
- The Phase 2 and Phase 3 result files, for the old→new mappings

Do not read `CLAUDE.md`. Do not run Revit, Excel, WPS, or any MCP tool (R1). Do not modify any file.

## Method

Produce one table row per R11 item. Every row carries: old `file:line` in the `.bak`, new `file:line`,
verdict (`SAME` / `RELOCATED` / `CHANGED`), and evidence — the actual code, quoted, not paraphrased.

Items to audit, at minimum:

1. **PageSetup normalization** — `PrintArea` from `range.Address[false,false]`, `Zoom = false`,
   `FitToPagesWide = 1`, `FitToPagesTall = 1`, all four margins `0`.
2. **PaperSize fallback chain** — `xlPaperEsheet` → `xlPaperA3` → keep current, both catches silent.
3. **`ExportAsFixedFormat` argument list** — all eight positional arguments, in order, unchanged.
4. **Render DPI** — `Dpi = 300`, `WithAnnotations = false`, and the full `Conversion.SavePng` argument list.
5. **Crop threshold** — `240`, four-directional scan, `IsNonWhitePixel` comparing Alpha/Red/Green/Blue.
6. **PNG encode** — `SKEncodedImageFormat.Png`, quality `100`.
7. **Region resolution order** — NamedRange → PrintArea → UsedRange, including each fallback branch.
8. **Named-range scope filtering** — which names appear for which sheet. The UI dropdown depends on this;
   an off-by-one in the scope test is silent and user-visible.
9. **COM release order** — child before parent; `Dispose` = `Close(false)` → release workbook → `Quit()` →
   release app → `GC.Collect()` + `GC.WaitForPendingFinalizers()`.
10. **Open-failure policy** — `false` from the provider, converted to `InvalidOperationException` with the
    original Vietnamese message at `ExcelSyncEngine.cs:162`.
11. **Export-failure policy** — the second `InvalidOperationException` and its message.
12. **UI enumeration failure policy** — swallow and return empty; no dialog, no throw, dropdowns just empty.
13. **Temp-PDF lifetime** — created and deleted; the delete now lives in the coordinator's `finally`. Verify
    it still runs on both the success and the failure path, and that it cannot mask a real export error.
14. **Native library candidate order** — assembly dir, `native/`, `runtimes/win-x64/native/`, unchanged for
    both `pdfium.dll` and `libSkiaSharp.dll`.
15. **`_suppressRowEvents` span** in the window (BUG-P3-01) — the guarded region is unchanged.
16. **Runtime folder anchor** — `GetRuntimeFolder`'s `typeof(...)` retarget resolves to the same directory,
    since it is the same assembly. Confirm rather than assume.

Also confirm: `GetActiveSheetName` and `ExportPrintAreaAsHighResImage` are absent from all new files, and
their absence is safe because they had zero callers.

## Verdict rules

- `PASS` — every item is `SAME` or `RELOCATED` with a relocation that cannot change observable behavior.
- `CONCERN` — an item is `CHANGED`, or a relocation could plausibly change behavior. State the exact
  scenario in which a user would notice, and name the owning task for a fix.
- `FAIL` — a locked R11 behavior is provably broken.

## Acceptance condition

Verdict on the first line, then all sixteen rows with quoted evidence on both sides. "Looks equivalent" is
not evidence; quote the code.
