## Runbook writing rules

- Numbered steps, one action per step. No step may require judgment the user has not been given.
- Every step states its **expected result** and **what to record**. A step whose outcome is not recorded
  is not evidence.
- Prefer artifacts the user can paste or attach: console output, file paths, PDF/PNG files, screenshots.
- Say explicitly which steps are safe on a production machine and which need a scratch copy of the file.
- Write in the user's language for operator-facing steps where that reduces ambiguity; keep technical
  identifiers verbatim.
- Do not ask the user to read source code or to interpret results. They run steps; `T5.1`/`T5.2` interpret.

## `EV-1` — WPS ProgID and late-bound member probe (same machine, WPS side)

Purpose: find out which ProgID a real WPS install registers, and which members actually exist.

Include:
1. WPS version identification — exact build number. The reported COM-registration breakage in builds
   `12.1.0.22529` / `12.1.0.22525` makes the version decisive for interpreting a failure.
2. A single copy-paste PowerShell snippet that probes each candidate ProgID with
   `[Type]::GetTypeFromProgID($id)` and prints ProgID plus resolved type or null. Cover the full chain
   from `T1.2`. **PowerShell, not `reg query`** — registry probing through a shell variable mangles
   backslashes and produced six false results on this machine; do not reintroduce it.
3. A member-existence probe against a live instance for every member in `T3.2`'s assumed-member list,
   printing member name plus present/absent. Give the user the exact snippet.
4. Explicit instructions to close all WPS windows first, and to confirm no orphaned `et.exe` remains
   afterwards (Task Manager or `tasklist`).
5. What to record: the version, the full ProgID table, the full member table, and any error text verbatim.

## `EV-2` — WPS end-to-end export and PDF fidelity (same machine, force the WPS branch)

Purpose: prove a real spreadsheet becomes a correct image in Revit through the WPS branch.

Both engines are on this one machine, and the coordinator prefers MS Excel (R10). To actually exercise
the WPS path, the user must make MS Excel unavailable for the run — e.g. temporarily rename/move the MS
Excel executable, or use whatever mechanism `T3.3`'s coordinator result documents for forcing detection
to skip MS Excel. Do not ask the user to uninstall MS Excel. State the exact mechanism from `T3.3`'s
result rather than inventing one; if `T3.3` did not provide one, say so and return `BLOCKED`.

Include:
1. Preconditions: the refactored build deployed, a test `.xlsx` with a named range, a print area, and a
   sheet with neither, plus the MS-Excel-unavailable step above. Confirm the coordinator actually picked
   the WPS provider (e.g. via a log line or debug output it emits) before trusting the rest of the run.
2. Steps covering: open the Excel-to-Revit window, sheet dropdown populates, region dropdown populates,
   run the update, image lands in the Revit view.
3. **Fidelity comparison**, the highest-risk unknown. Have the user produce the same region twice on this
   machine — once through the MS path (Excel restored), once through the WPS path (Excel unavailable) —
   then compare: print-area bounds, scaling/fit, margins, font substitution, merged cells, line weights,
   and the crop result. Ask for both PNGs and both PDFs.
4. Named-range scope parity: does the region dropdown show the same names as MS Excel, for the same file?
5. Cleanup check: no orphaned `et.exe` after the operation; temp PDFs removed from `%TEMP%`
   (`ArcTool_ExcelSync_*.pdf`).
6. What to record: pass/fail per step, both image files, both PDFs, and any dialog text verbatim.

## `EV-3` — MS Excel non-regression matrix (dev/MS machine)

Purpose: prove the refactor changed nothing for existing users. This is the matrix that matters most.

Include, at minimum:
1. Named range → export; print area → export; neither (UsedRange fallback) → export.
2. Sheet dropdown load, region dropdown load, row reload with a previously saved selection — confirm the
   selection is restored (guards BUG-P3-01 and the `defaultToFirstSheet` logic).
3. Failure paths: missing file, wrong sheet name, locked/open-in-Excel file. Confirm the Vietnamese
   `InvalidOperationException` messages appear exactly as before.
4. A visual before/after comparison of the produced PNG against a pre-refactor export of the same region,
   to catch a crop or DPI regression.
5. One targeted step per `CONCERN` row from `T4.1`.
6. Cleanup: no orphaned `EXCEL.EXE`; no leftover `ArcTool_ExcelSync_*.pdf` in `%TEMP%`.
7. What to record: pass/fail per row, screenshots, and the temp-folder listing.
