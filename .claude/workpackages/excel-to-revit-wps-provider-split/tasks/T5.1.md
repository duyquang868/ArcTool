# T5.1 — Analyze `EV-1` + `EV-2` WPS runtime evidence

- depends on: `T4.2`, plus operator-returned `EV-1` and `EV-2`
- write_scope: result only → `results/T5.1_result.md`
- model: sonnet

## Objective

Turn the operator's WPS evidence into a decision: does the WPS branch work as written, does it need a
patch, or is WPS COM automation unusable on that install?

## Inputs you may read

- `01_SHARED_CONTRACT.md` §5 and §6 (this package)
- The `EV-1` and `EV-2` artifacts, **by the paths the master gives you** — probe output, PDFs, PNGs,
  screenshots, error text
- `results/T1.2_result.md` — the assumption list you are testing
- `results/T3.2_result.md` — the assumed-member list and the constant provenance table
- `ArcTool.Core/Services/Excel/WpsWorkbookPdfExporter.cs` — the code under test

Do not read `CLAUDE.md`. Do not run Revit, Excel, WPS, or any MCP tool (R1) — you interpret the operator's
evidence, you do not generate your own. Do not modify source; `T5.1b` does that if the master opens it.

## What to determine

1. **ProgID reality.** Which ProgID resolved on the real install? Is the probe order in the shipped code
   correct, incomplete, or in the wrong order? If a ProgID resolved that is not in our chain, that is a
   required patch.
2. **Member reality.** For every member in `T3.2`'s assumed-member list: present, absent, or present with a
   different signature. Flag every mismatch and classify each as fatal or tolerable, using `T1.2`'s ruling
   for that member.
3. **The `Address[false,false]` parameterized property** — the single most likely late-binding failure.
   State exactly what the evidence shows and whether the shipped fallback was needed and worked.
4. **Constant correctness.** Did any `UNSOURCED` constant get exercised? Did a paper-size or format value
   produce a wrong-looking PDF? A wrong `PaperSize` corrupts layout silently, so judge this from the PDF,
   not from the absence of an exception.
5. **PDF file existence check.** Confirm whether the "verify the PDF exists after `ExportAsFixedFormat`"
   guard fired. If WPS returned without throwing and without producing a file, that guard is the only thing
   that prevented a confusing downstream error — say so.
6. **Fidelity verdict.** Compare the WPS output against the MS output on: print-area bounds, scaling/fit,
   margins, font substitution, merged cells, line weights, crop result. Rate each `MATCH`,
   `ACCEPTABLE_DIFFERENCE`, or `UNACCEPTABLE`. Judge from the supplied images and PDFs, not from theory.
7. **Named-range scope parity** — did the region dropdown show the same names as MS Excel for the same file?
8. **Version correlation.** If COM failed entirely, correlate against the reported breakage in builds
   `12.1.0.22529` / `12.1.0.22525`. Distinguish "our code is wrong" from "this WPS build's COM registration
   is broken" — they lead to opposite next actions.
9. **Process hygiene.** Orphaned `et.exe`? Leftover `ArcTool_ExcelSync_*.pdf` in `%TEMP%`? Either indicates
   a release or cleanup defect.

## Verdict rules

- `PASS` — WPS branch works end to end; fidelity is `MATCH` or `ACCEPTABLE_DIFFERENCE` throughout; no patch
  needed.
- `PATCH_REQUIRED` — a specific, code-fixable defect exists. Specify the exact change for `T5.1b`: which
  member, which ProgID, which constant, which call shape. Vague findings are not actionable.
- `ENVIRONMENT_BLOCKED` — WPS COM automation is unusable on that install for reasons outside our code
  (broken registration, WPS edition without COM). Recommend what to tell the user, and state clearly that
  the MS branch is unaffected.
- `EVIDENCE_INSUFFICIENT` — name the missing artifact and the exact runbook step that must be re-run.

## Acceptance condition

Verdict on the first line, then the nine determinations, each citing the specific evidence artifact it rests
on. Never state a WPS behavior as fact without pointing to the artifact that shows it.

## What downstream needs from you

`T5.3` weighs your verdict against `T5.2`. `T5.1b`, if opened, implements exactly your specified patch —
so specify it at the level of a code change, not an intention.
