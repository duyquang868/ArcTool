# T5.2 — Analyze `EV-3` MS Excel non-regression evidence

- depends on: `T4.2`, plus operator-returned `EV-3`
- write_scope: result only → `results/T5.2_result.md`
- model: sonnet

## Objective

Confirm from runtime evidence that MS Excel users see no change. `T4.1` argued this statically; this task
checks whether reality agrees.

## Inputs you may read

- `01_SHARED_CONTRACT.md` §6 (this package)
- The `EV-3` artifacts, **by the paths the master gives you** — pass/fail matrix, screenshots, before/after
  PNGs, temp-folder listings, dialog text
- `results/T4.1_result.md` — the static parity conclusions, especially every `CONCERN` row
- `results/T3.7_result.md` — the build and isolation audit

Do not read `CLAUDE.md`. Do not run Revit, Excel, WPS, or any MCP tool (R1). Do not modify source files.

## What to determine

1. **Matrix completeness.** Was every `EV-3` row executed? An unexecuted row is not a pass. List omissions.
2. **Three region paths** — named range, print area, UsedRange fallback — each produced the expected image.
3. **Image equivalence.** Compare the before/after PNGs for the same region. Look specifically for a crop
   regression (extra or missing white margin, which would mean the threshold-240 scan changed) and a DPI
   regression (dimensions differ, which would mean the 300 DPI render changed). Report pixel dimensions if
   the artifacts allow it.
4. **UI behavior.** Sheet dropdown populated, region dropdown populated, saved selection restored on row
   reload. A regression here is the BUG-P3-01 `_suppressRowEvents` class of bug, so treat any dropdown
   flicker, reset, or duplicate-load report as significant rather than cosmetic.
5. **Failure-path messages.** Missing file, wrong sheet, locked file — did the original Vietnamese
   `InvalidOperationException` text appear unchanged? Quote what the operator reported and compare it to
   the strings in `ExcelSyncEngine.cs`.
6. **Each `T4.1` `CONCERN` row** — did the targeted runtime step confirm or refute the concern? Resolve every
   one; none may be left open.
7. **Process and temp hygiene.** Orphaned `EXCEL.EXE` after the operation would mean the COM release order
   regressed. Leftover `ArcTool_ExcelSync_*.pdf` in `%TEMP%` would mean the coordinator's `finally` does not
   run on every path. Both are release-blocking.
8. **Revit-side invariants untouched** — the image lands in the same view, at the same scale behavior
   (Smart Scale), with the same timestamp behavior. Judge only from what the evidence shows; do not infer.

## Verdict rules

- `PASS` — full matrix executed, no regression, every `T4.1` `CONCERN` resolved.
- `REGRESSION` — a behavior changed for MS Excel users. Name the symptom, the likely owning file, and the
  minimum fix. This blocks the package regardless of how the WPS branch performed.
- `EVIDENCE_INSUFFICIENT` — name the missing rows and the exact runbook steps to re-run.

## Acceptance condition

Verdict on the first line, then the eight determinations, each citing the evidence artifact it rests on, then
an explicit resolution line for every `T4.1` `CONCERN` row.

## What downstream needs from you

`T5.3` treats an MS regression as fatal to the package even if WPS passed — the working majority outranks the
new capability. Be unambiguous about whether a regression exists.
