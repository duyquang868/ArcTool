# T5.3 — Final verdict for the package

- depends on: `T5.1`, `T5.2`
- write_scope: result only → `results/T5.3_result.md`
- model: sonnet

## Objective

Decide whether the package closes, and state honestly what is proven versus assumed. This verdict is what
gets written into durable memory, so an overstated claim here becomes a false invariant later.

## Inputs you may read

- `01_SHARED_CONTRACT.md` §8 (the ten acceptance gates), `03_TASK_MANIFEST.md`
- `results/T5.1_result.md`, `results/T5.2_result.md`, `results/T4.1_result.md`, `results/T3.7_result.md`,
  `results/T2.3_result.md`
- Other result files only if you must resolve a contradiction

Do not read `CLAUDE.md`. Do not run Revit, Excel, WPS, or any MCP tool (R1). Do not modify source files.

## What to produce

1. **Gate-by-gate ruling.** Walk contract §8 gates 1 through 10. Each gets `MET`, `NOT_MET`, or
   `MET_WITH_CAVEAT` plus the result file that proves it. No gate may be ruled on by assertion.
2. **Verdict.**
   - `GO` — MS Excel parity proven and WPS either `PASS` or `ENVIRONMENT_BLOCKED` with the limitation
     documented. Note that `ENVIRONMENT_BLOCKED` can still be `GO`: the refactor is complete and correct
     even if that particular WPS install cannot do COM. Say which case applies.
   - `GO_WITH_FOLLOWUP` — closeable, but a bounded follow-up is needed. Name it precisely and say whether it
     belongs in this package (`T5.1b`) or a future one.
   - `NO_GO` — an MS Excel regression exists, or a gate is unmet in a way that cannot be documented away. An
     MS regression is fatal regardless of WPS results; the working majority outranks the new capability.
3. **Proven-versus-assumed ledger.** Two explicit lists. Every WPS claim not backed by an `EV-1`/`EV-2`
   artifact belongs in the assumed column. This is the ledger `T6.1` copies into durable memory, so
   precision here directly determines whether a future session is misled.
4. **Residual risk list.** What can still bite a user, ranked, with the trigger condition for each. Include
   at minimum: WPS builds with broken COM registration, fidelity differences the operator rated
   `ACCEPTABLE_DIFFERENCE`, and any member the WPS branch assumes but never exercised.
5. **What the user must know**, in three sentences or fewer: what now works, what is unverified, what to do
   if the WPS path fails on a different machine.

## Acceptance condition

Verdict on the first line, then the ten gate rulings, the two-column ledger, the ranked residual risks, and
the three-sentence user summary.

## What downstream needs from you

Phase 6 starts only on `GO` or `GO_WITH_FOLLOWUP`. `T6.1` persists your ledger verbatim; `T6.2` writes the
closure message from your user summary.
