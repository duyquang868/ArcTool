# T6.2 — Draft the final closure message

- depends on: `T6.1`
- write_scope: result only → `results/T6.2_result.md`
- model: sonnet

## Objective

Draft the message the master sends the user to close the package. Written for someone who did not read a
single result file.

## Inputs you may read

- `results/T5.3_result.md` — the verdict, the proven/assumed ledger, the residual risks
- `results/T6.1_result.md` — what was persisted where
- `06_EXECUTION_STATE.md` — final task statuses

Do not read source files. Do not read `CLAUDE.md`. Do not run Revit, Excel, WPS, or any MCP tool (R1).

## Message requirements

- Vietnamese, matching how the user wrote the request. Keep technical identifiers (file paths, type names,
  ProgIDs) verbatim in their original form.
- Lead with the outcome. No preamble, no restatement of the task, no narration of the process.
- Short. Prose over bullets except where a list is genuinely a list. No headers unless the content needs them.
- Content, in order:
  1. What now works — Excel to Revit runs with MS Excel or WPS, auto-detected, MS first.
  2. The five new files and the backup path, so the user can find them.
  3. What is proven versus unverified — copy the ledger's substance without softening it. If the WPS branch is
     `ENVIRONMENT_BLOCKED` or untested, say so plainly.
  4. Residual risks worth knowing, at most the top two or three.
  5. Where the durable record lives.
  6. The re-index offer, phrased as a genuine choice: run now, or defer to a fresh chat. Do not run it.
  7. One line noting the phase is closed and the next phase starts in a new chat.
- Do not claim anything `T5.3` put in the assumed column. Do not overstate WPS support. Do not add
  congratulation or filler.

## Acceptance condition

Your result file contains the draft message ready to send, and nothing else of substance. The master may
adjust wording but should not need to restructure it.
