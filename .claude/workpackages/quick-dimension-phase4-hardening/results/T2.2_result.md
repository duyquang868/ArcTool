   - `allReferencesOwnedBySelectedWallOrOpenings="true"`
   - `allSegmentLengthsWithinTolerance="true"`
6. XML `<ExpectedCandidates candidateCount="8" />`
7. No crash, no misleading diagnostic

### 5.2 Unsupported-by-design

**Not applicable** for this fixture. The fixture is well within MVP scope:
- Straight non-curtain host wall ✓
- Hosted Door/Window openings only ✓
- Plan view ✓
- No grids (grid is disabled in wall-axis flow) ✓
- No arc walls, no curtain walls ✓
- No linked models ✓

There is no honest reason for the MVP to refuse this fixture. Any failure is a defect.

### 5.3 Defect

The run is a **Defect** if ANY of these hold:

1. No dimension created, with no honest diagnostic explaining why (silent failure)
2. Dimension created but segment count ≠ 7
3. Any segment length differs from the oracle by more than **0.1 mm**
4. XML audit shows `referenceOrderRelation="Mismatch"` or partial `"Reversed"`
5. XML audit shows any gate `false`
6. XML audit shows `candidateCount` ≠ 8 or `segmentCount` ≠ 7
7. Crash or exception during execution
8. Misleading diagnostic (e.g., "no valid candidates" when 8 exist)
9. Dimension witnesses point to wrong elements (e.g., a grid, a non-selected wall)

**Special case: complete `Reversed`** — If `referenceOrderRelation="Reversed"` AND all segment lengths are correct AND all gates are `true`, this counts as **Supported** (the dimension is correct, just built in reverse candidate order). However, for this fixture with single-shell runs, `Exact` is expected.

## 8. Assumptions and boundary conditions

### 8.1 Assumptions made (explicit)

1. **Wall anchor projection:** Resolved wall end anchors project at the wall axis endpoints (0 and 8000 mm) regardless of shell selection. Shell direction affects which reference object is used (Interior face vs Exterior face), not the projected station along the axis.

2. **No shell-dependent offset:** The fixture spec (T2.1) defines the wall axis as the geometric line from 0 to 8000. The contract states stations are "physical projected station on the wall axis." Therefore, shell selection does not introduce a systematic offset or extension beyond the axis bounds.

3. **BUG-10/BUG-11 fixes hold:** `ResolveCandidateElementId` and `TryResolveReferenceOwnedPoint` are working as locked (contract R4). This ensures candidate metadata is reference-owned and stable.

4. **No tolerance edge cases:** All clearances exceed 1000 mm (T2.1), well above `DuplicateTolerance` (1e-4 ft ≈ 0.03 mm). No station collision expected.

### 8.2 What this oracle cannot predict

1. **Exact XML reference strings:** The `<Candidate reference="...">` attribute contains Revit's internal reference encoding, which this oracle cannot derive without runtime evidence.

2. **Dimension ElementId value:** The committed dimension's id is assigned by Revit at creation time.

3. **Dimension visual appearance details:** Line weight, text size, leader style (not relevant to functional correctness).

4. **Execution time:** Phase 5 will measure that; out of scope here.

### 8.3 Boundary conditions not tested by this fixture

(These are Session 4.2 and 4.3 cases, not Session 4.1)

- Empty wall (no openings)
- Single opening
- Close-spaced openings (< 1 mm clearance)
- End-flush opening (jamb coincides with wall anchor)
- Flipped/mirrored opening instances
- Mid-run T-junction host wall
- Grid presence (should fail safely with "Grid disabled" diagnostic)
