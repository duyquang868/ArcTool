## 1. Hypothesis under test

Hypothesis: after BUG-11’s reference-owned station fix, a hosted Door/Window instance’s mirror and/or flip state has no residual effect on the physical projected stations, reference ordering, or segment values of its two jamb candidates when host wall geometry and opening placement are otherwise held constant.

This is the narrowest hypothesis that matches the shared contract’s unresolved point in section 5 and T3.2’s preserved risk: a possible orientation-correlated jamb inversion, duplication, or displacement.

## 2. Minimum discriminating case set

To isolate orientation from unrelated geometry, the probe should use the same host-wall fixture and the same family/type, dimensions, insertion station, sill/head settings, facing side, and wall side pick in every case. Only orientation flags may change.

### Required minimum pair
A two-case pair is sufficient to settle the practical question for EV-2 if it is truly controlled:

1. **Baseline case** — one hosted opening in its ordinary non-mirrored, non-flipped state.
2. **Orientation-variant case** — the same hosted opening after applying the project’s available orientation toggle(s) so the instance reports at least one changed state among Mirrored / HandFlipped / FacingFlipped.

Why this minimum is sufficient:
- The hypothesis is binary: orientation-neutral vs orientation-sensitive.
- If the geometry and placement are unchanged and only orientation state changes, any station/order/value change is attributable to orientation.
- EV-2 only needs a discriminating observation probe, not an exhaustive family-behavior census.

### Preferred stronger pairing when the family supports both toggles cleanly
If the operator can create them without changing placement geometry, use four subcases for stronger diagnosis:
- A. baseline: not mirrored, not flipped
- B. hand/facing flip only
- C. mirror only
- D. mirror + flip

This stronger set is not required for PASS here, but it improves attribution if one orientation control behaves differently from another.

### Geometry controls that must stay fixed across the pair
- same straight non-curtain host wall;
- same wall length and no joins/mid-run conditions;
- same picked shell/side for Quick Dimension;
- same opening family and type;
- same insertion station on wall axis;
- same opening width;
- same physical cut opening in the wall after the orientation change.

Any change to width, insertion point, host side, wall side pick, or surrounding geometry invalidates the probe because it reintroduces non-orientation explanations for station drift.

## 4. How later EV-2 judges answer the question from the evidence alone

A later judge should be able to decide the probe from the evidence bundle without reading source code by checking the following comparison table.

### Comparison rule set
Compare baseline vs orientation-variant case on the same fixture:

1. **Orientation actually changed**
   - At least one orientation flag differs between the two subcases.
   - If no flag differs, the probe is inconclusive.

2. **Physical placement stayed fixed**
   - Opening appears in the same wall location with the same width.
   - If location/width changed, the probe is invalid.

3. **Created/no-created outcome parity**
   - Supported expectation from T3.2 is that both cases create a dimension.
   - A no-created result only in the orientation variant is immediate falsification unless another explicit non-orientation cause is documented.

4. **Jamb-station parity**
   - The two projected jamb stations in the variant must match the baseline’s physical pair, allowing only the already-accepted whole-chain full reversal interpretation.
   - No extra displacement, collapse, or one-sided drift is acceptable.

5. **Order relation parity**
   - `referenceOrderRelation` must remain `Exact` or complete `Reversed`.
   - Any orientation-specific `Mismatch` or local/non-global swap falsifies the hypothesis.

6. **Segment-value parity**
   - Segment values must match between baseline and variant within the package’s supported acceptance usage (the Session 4.2 supported vocabulary from the shared contract uses 0.1 mm for predicted segment deltas).
   - Any orientation-only segment-value change falsifies the hypothesis.

7. **No hidden reduction**
   - No orientation-specific missing jamb, duplicate collapse, or silent station drop is acceptable.

## 5. Confirmation criteria

The hypothesis is confirmed when all of the following are true:

1. The compared cases use the same host geometry, same family/type, same insertion station, same width, and same side pick.
2. At least one orientation state flag differs between baseline and variant.
3. Both cases produce the expected supported outcome: created dimension.
4. The tested opening contributes two jamb stations in both cases.
5. The variant’s jamb stations are numerically the same physical pair as the baseline’s, allowing at most complete whole-chain reversal but not a local opening-only swap.
6. `referenceOrderRelation` is `Exact` or complete `Reversed` in both cases.
7. Segment values match the same physical station set with no orientation-only drift.
8. No duplicate/collision diagnostic appears only because of the orientation change.
9. No visible inversion is observed beyond a whole-chain reversal already validated by the audit.

Interpretation: mirror/flip is operationally irrelevant to wall-axis chain correctness for that controlled opening case.

---

## 6. Falsification criteria

The hypothesis is falsified by any one of the following, provided the geometry controls remained fixed:

1. The orientation-variant case fails to create a dimension while the baseline creates one.
2. One jamb is missing, duplicated, or collapsed only in the orientation-variant case.
3. The two jamb stations move, swap locally, or become displaced only after the orientation change.
4. `referenceOrderRelation` becomes `Mismatch`, or exhibits a local/non-global swap pattern inconsistent with `Exact` or full `Reversed`.
5. Segment values change in the orientation variant without any non-orientation geometry change.
6. The operator observes a visible left/right inversion that is not explained by a valid whole-chain reversal and is accompanied by station/order/value inconsistency.

Interpretation: some residual orientation sensitivity remains despite BUG-11’s reference-owned station derivation.
