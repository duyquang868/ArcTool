## 2. Session 4.3 verdict

**PASS.** The package proved honest safe-failure across the whole Grid matrix (V1..V4): every variant reported the exact disabled-Grid diagnostic, none silently altered a candidate, reference, or segment value, none crashed, and none produced a `Mismatch` order relation. Per the shared-contract acceptance vocabulary, all four are **Unsupported-by-design**, not Defect. No Grid variant triggers the T4.5 `NO_GO` condition ("any Grid variant produced a Defect outcome").

Session 4.3 is framed strictly as safe-failure proof, consistent with the Phase 4 rescope (`01_SHARED_CONTRACT.md` §5, `T1.3`): the mission never asked whether Grid dimensioning could be made to work, only whether the MVP fails safely on content it does not support. Nothing in this verdict describes accidental support widening as success.

### Product-scope directive (recorded verbatim, project owner, dated 2026-08-08)

- Quick Dimension's product scope is batch dimensioning of wall-hosted objects only. Grid dimensioning is explicitly **not** a product target; the owner controls grids manually.
- Grid support expansion must **never** be proposed as follow-up work from Session 4.3. The only legitimate Session 4.3 value is confirming grids do not perturb the wall-hosted chain — which is exactly what V1..V4 confirmed.
- This directive overrides any implicit reading of the roadmap's original Session 4.3 wording as a path toward Grid feature work. It does not reopen or contradict the `T1.3` safe-failure rescope; it reinforces it with an explicit owner-level product boundary.

### Limitation of the variant matrix (recorded)

Selection rejects non-Wall elements before any grid geometry or view state (cropped/hidden/arc) is ever evaluated. Consequently V1..V4 are weakly discriminating by construction: the wall-axis flow's `CollectWallAxisCandidates` emits the Grid-disabled diagnostic unconditionally, before grid geometry or view state can influence anything. The four runs did not exercise four independently different code paths reacting to grid state — they exercised the same early-exit path four times under different scene dressing. The evidence therefore confirms **non-interference** (grids present in the model/view do not perturb the wall-hosted chain), not four independently validated behaviors. This limitation does not downgrade the PASS verdict — non-interference is exactly what a safe-failure matrix needs to show — but it must not be cited later as broader proof of grid-state-aware handling.
