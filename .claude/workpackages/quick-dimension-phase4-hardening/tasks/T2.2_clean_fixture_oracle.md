## Objective
Write the pre-committed analytic oracle for the clean fixture before any runtime evidence is requested.

## Do
1. Compute the expected candidate order along the wall axis.
2. Compute the expected segment values in millimetres.
3. State the expected audit outcome:
   - `referenceOrderRelation`,
   - identity/owner/segment gates,
   - candidate count and segment count expectations.
4. State what outcomes would count as Supported, Unsupported-by-design, or Defect for this fixture.
5. Keep the oracle human-checkable; show the arithmetic, not just the answer.

## PASS only if
- The expected values are fully determined from `T2.1` with no runtime facts mixed in.
- The oracle can be used by `T2.4` line-by-line against XML and screenshot evidence.
- The oracle assumes no audit weakening.
