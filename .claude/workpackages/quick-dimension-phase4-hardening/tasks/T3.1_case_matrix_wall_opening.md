## Objective
Author the full Session 4.2 case matrix for supported and edge-condition wall/opening scenarios.

## Do
1. Define a compact but complete case list covering at least:
   - empty wall,
   - single opening,
   - several openings,
   - close-spaced openings,
   - opening flush with a resolved end anchor,
   - mirrored/flipped family instances,
   - mid-run T-junction host condition.
2. For each case, state:
   - why it belongs in the matrix,
   - whether it is expected to be Supported or Unsupported-by-design going in,
   - what evidence must be visible.
3. Keep Grid, linked content, arc walls, and rollback out of scope.
4. Minimize redundant cases while preserving coverage.

## PASS only if
- The matrix covers the unresolved risks named in the shared contract.
- Every case has a clear purpose.
- No case widens scope outside the wall-axis MVP.

## BLOCKED if
- Session 4.1 leaves the feature too unstable to define a meaningful matrix.
