## Objective
Design behaviour-neutral read-only timing instrumentation for the Quick Dimension collection path, and specify exactly where it emits.

## Do
1. Choose the minimum timing boundaries that would localize a real hotspot, for example:
   - total collection time,
   - wall-end anchor collection,
   - mid-run joint collection,
   - opening projection collection,
   - duplicate-station reduction.
2. Specify where timing values are emitted so they reach the operator without new UI:
   - the existing read-only XML log path is preferred.
3. State the neutrality requirements explicitly:
   - no new Revit object allocation in the measured path,
   - no change to candidate values, stations, diagnostics, or reference identity,
   - no change to audit gates,
   - no change to command result semantics.
4. State how the instrumentation stays debug-appropriate and easy to remove or gate later.
5. Name the exact files that will need edits and confirm they match the allowed write scope for `T5.2`.

## PASS only if
- The design can be implemented inside `QuickDimensionReadOnlyEngine.cs` and `QuickDimensionReadOnlyXmlLogService.cs` only.
- Neutrality is argued concretely, not asserted.
- The emitted data is sufficient to identify one dominant cost center.

## BLOCKED if
- Timing cannot be emitted without touching a no-touch file.

## Downstream needs
- `T5.2` needs an unambiguous patch intent and neutrality constraints.
