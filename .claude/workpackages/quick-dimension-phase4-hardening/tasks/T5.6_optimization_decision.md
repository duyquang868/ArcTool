## Objective
Decide whether the measured evidence justifies one optimization, or whether optimizing is the wrong trade for a feature that is already correct.

## Do
1. Weigh the measured hotspot against:
   - interactive acceptability,
   - regression risk to a just-stabilized collector,
   - the single-file constraint.
2. Decide GO or NO_GO explicitly.
3. If GO, name exactly one target file from the allowed set and justify the choice from evidence.
4. If NO_GO, state plainly that the feature is fast enough for its intended one-wall interactive use.

## PASS only if
- The decision is unambiguous.
- A GO decision names exactly one collector file.
- A NO_GO decision is framed as a valid measured outcome, not a failure.

## Note
`NO_GO` here means "do not optimize"; it does **not** stop the package. `T5.7` records the rejection and the phase continues to its verdict.
