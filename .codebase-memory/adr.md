## PURPOSE
Record stable architecture decisions that should guide future ArcTool implementation, especially Quick Dimension and Revit API feature work.

## STACK
ArcTool.Core targets Autodesk Revit 2026 API with C# / .NET 8.0, WPF, and limited WinForms. Quick Dimension production contracts live under `ArcTool.Core/Models`; production read-only geometry helpers and collectors live under `ArcTool.Core/Services`.

## ARCHITECTURE
Quick Dimension Phase 2 is a read-only engine boundary. Phase 1 spike models/services remain evidence and must not be mutated into production contracts. Production QD models are centralized in `QuickDimensionContract.cs`: options, line context, candidates, diagnostics, per-source summaries, and read-only result. Candidate contracts may carry `ElementId`, `Reference`, `XYZ`, strings, enums, and scalar values, but must not retain live Revit `Element` objects across service boundaries. `QuickDimensionGeometryService.cs` is the transaction-free/document-free math boundary for Phase 2; it must not collect elements, open transactions, or call `NewDimension`. Dimension creation begins only in Phase 3.

### ADR-2026-06-11: Quick Dimension pivots from cross-cutting intersection to wall-axis projection
Status: ACCEPTED and implemented in the Phase 2.6 read-only smoke path as of 2026-07-12.
Decision: The Quick Dimension MVP input model changes from "user draws a dimension line across the plan" to "user selects ONE host Wall, then picks a side (left/right)". The selected wall's `LocationCurve` (Line only in MVP) IS the dimension axis, even when the wall is skewed in plan. The tool no longer asks the user to draw a dimension line. References are gathered ONLY from the selected wall: the wall's two end anchors plus every Door/Window opening hosted in that wall, each opening contributing BOTH left and right jamb references. All reference points are PROJECTED onto the wall axis (signed parameter along the axis) and ordered to build the chain. A second user pick on the left or right of the wall sets the dimension placement side (side sign), captured in the contract from Phase 2 so Phase 3 placement has enough information.
Rationale: User confirmed the desired result measures openings ALONG a wall, which is how Revit "dimension along a wall" behaves. The previous intersection model answered "what does the drawn line physically cross", which structurally cannot return both jambs of an opening and rejects walls parallel to the line — the opposite of the requirement. This pivot resolves the observed Window collected-but-accepted=0 and Door single-jamb symptoms at the model level rather than patching collectors.
Implementation: `QuickDimensionLineContext.CreateFromWallAxis()` builds the axis from selected Wall `LocationCurve` endpoints and computes `SideSign` from the side pick. `QuickDimensionReadOnlySummaryCommand` uses `Selection.PickObject(ObjectType.Element, ISelectionFilter, string)` for the wall and `Selection.PickPoint(ObjectSnapTypes.None, string)` for side placement, rejecting curtain/non-line walls and ambiguous side picks. `QuickDimensionReadOnlyEngine` dispatches `IsWallAxis` contexts to selected-wall-only collection. `QuickDimensionWallCandidateCollector.CollectSelectedWallEndAnchors()` extracts the wall start/end anchors from wall geometry planar end faces with `Options.ComputeReferences = true`; Revit 2026 `HostObjectUtils` exposes `GetSideFaces`, `GetTopFaces`, and `GetBottomFaces`, not `GetEndFaces`, so wall ends must not use a non-existent utility method. `QuickDimensionReferenceStrategy.WallEndFace` records this anchor strategy separately from legacy `WallSideFace`. `QuickDimensionDoorWindowCandidateCollector.CollectOpeningsAlongWallAxis()` filters hosted openings by selected host wall id and projects both left/right jamb candidates onto the wall axis.
Consequences: `QuickDimensionCandidate.ParameterOnDimensionLine` means "projected coordinate on wall axis" in the main flow. Grid and other-wall sources drop out of the main flow and are explicitly disabled by the projection dispatch; they may return later as an opt-in legacy cross-cutting path. The intersection path (`TryIntersectSegmentWithDimensionLine2D`) and the parallel guard (`IsNearlyParallel` / `ParallelToDimensionLine`) are retained only for deprecated/optional cross-cutting collectors and must not gate the wall-axis main flow. Ordering, source-aware dedupe, diagnostics, summaries, and the `QuickDimensionReadOnlyResult` contract shape are retained. Phase 1 spike services/models/commands are untouched.
Scope guard: MVP supports active Plan Views and straight non-curtain host walls only. Arc/non-line host walls, curtain walls, linked models, columns, grids, and non-selected walls are out of scope for the wall-axis main flow.

### ADR-2026-07-12: Wall-end anchor = physical solid caps by min/max projected station
Status: ACCEPTED and implemented as part of the Phase 2.6 smoke-fix loop on 2026-07-12.
Decision: Wall-end anchors are the two wall-direction-aligned `PlanarFace` references whose centroids project to the minimum and maximum stations on the selected wall axis. These min/max faces are the physical wall solid end caps used for drafting-visible wall-corner anchoring. `QuickDimensionOptions.WallEndStationTolerance` remains only as a degeneracy guard when min/max stations are not distinct.
Rationale: Wall `LocationCurve` endpoints can lie on the centerlines of joining walls, not at the visible wall-corner/intersection. In a 200 mm butt-join, the physical start cap may be offset about 100 mm from station 0. The earlier "face must be near station 0 or Length" rule rejected the real cap and left the first opening jamb as the first candidate. Opening reveal/jamb faces share the wall-axis normal but sit between the two physical solid caps, so min/max projected station separates solid ends from openings without anchoring to centerline endpoints.
Implementation: `QuickDimensionWallCandidateCollector.GetBestWallEndFaceCandidates` collects all wall-direction-aligned planar face candidates with `Options.ComputeReferences = true`, computes station directly via `QuickDimensionLineContext.ProjectParameter`, then selects `OrderBy(ParameterOnDimensionLine).First()` and `OrderByDescending(ParameterOnDimensionLine).First()`. `CollectWallEndFaceCandidates` does not call `TryProjectPointToPickedSpan`, so physical caps slightly outside the LocationCurve span due to joins are not silently dropped.
Consequences: Wall-end anchors now match the physical wall corner/intersection seen by the user instead of the LocationCurve centerline endpoint. Opening jamb faces are not used as wall anchors because they are interior to the min/max caps. This rule is scoped to straight non-curtain walls in MVP; arc, stacked, curtain, or heavily modified wall geometry still requires explicit future validation.

### ADR-2026-07-12: Chain-dimension readiness requires distinct projected stations
Status: ACCEPTED and implemented as part of the Phase 2.6 smoke-fix on 2026-07-12.
Decision: `QuickDimensionReadOnlyResult.CanCreateChainDimension` is true only when there are at least two final candidates AND every final candidate sits at a distinct projected station within `QuickDimensionOptions.DuplicateTolerance`. `QuickDimensionReadOnlyEngine` performs a global projected-station dedupe after source-aware dedupe; each removed collision emits a `QuickDimensionRejectedReason.DuplicateStation` diagnostic that names the kept candidate.
Rationale: Chain dimensions cannot use zero-length segments. Two candidates at the same projected station (for example a wall-end face collision with an opening jamb, or two touching openings sharing a jamb station) would either produce zero-length dimension segments or Revit-side rejection when handed to `NewDimension` in Phase 3. Reporting readiness only when stations are distinct is safer than trusting `CandidateCount >= 2` alone.
Implementation: `QuickDimensionReadOnlyEngine.RemoveDuplicateStations` runs after `QuickDimensionGeometryService.DeduplicateCandidates`. It sorts candidates by station, keeps the first candidate at each station, and emits a diagnostic for any dropped collision. `QuickDimensionReadOnlyResult.CanCreateChainDimension` uses a private `CountDistinctStations` helper backed by `DuplicateTolerance`.
Consequences: Read-only summary now reports chain readiness accurately, so future Phase 3 code can rely on `CanCreateChainDimension` as a real precondition. Diagnostics preserve the full audit trail for collision cases, keeping the "explain what was ignored" invariant.

### ADR-2026-07-12: Read-only summary uses millimeters for user-visible values
Status: ACCEPTED and implemented as part of the Phase 2.6 smoke-fix on 2026-07-12.
Decision: Any user-visible measurement rendered by `QuickDimensionReadOnlySummaryCommand` (wall-axis length and each ordered candidate's `t`) is converted to millimeters via `UnitUtils.ConvertFromInternalUnits(value, UnitTypeId.Millimeters)`. Diagnostics that surface station or tolerance values in the dialog (missing wall-end faces, duplicate station collisions) also emit millimeters.
Rationale: The user works in millimeters. The initial smoke output printed values in Revit internal feet, which made the smoke report unreadable and blocked verification of correctness at a glance.
Implementation: Storage and internal math remain in Revit internal feet; only presentation-layer strings are converted. Internal APIs (`ProjectParameter`, `Length`, `WallEndStationTolerance`, `DuplicateTolerance`) continue to accept and return internal feet.
Consequences: Presentation and math stay separated. Any new user-facing text in Quick Dimension must call `UnitUtils.ConvertFromInternalUnits(..., UnitTypeId.Millimeters)` before formatting.

## PATTERNS
Use domain-prefixed enums for new models. Keep QD options and results immutable or near-immutable. Keep source-aware diagnostics for both accepted and rejected elements. Centralize axis normalization in `QuickDimensionLineContext` so collectors do not duplicate direction/span/projection math. For the wall-axis projection model, the participation test is point projection onto the selected wall axis (`ProjectParameter` within `[0, Length]`) for openings, while wall-end anchors use min/max projected station among physical solid-cap candidates and are not forced to match LocationCurve endpoint stations. Door/Window openings hosted in the selected wall must contribute BOTH left and right jamb references projected onto the wall axis; build opening jamb points along the WALL direction. Dedupe must remain source-aware and conservative so Door/Window left/right references on the same instance are preserved. Wall-end anchors use geometry-derived planar face references (`WallEndFace`) from min/max projected station, while legacy side-face wall references (`WallSideFace`) remain tied to the optional cross-cutting path. Chain-dimension readiness must never be inferred from raw candidate count alone; enforce distinct projected stations before declaring readiness. User-facing values render in millimeters via `UnitUtils.ConvertFromInternalUnits` while internal math stays in Revit internal feet.

## TRADEOFFS
The contracts intentionally reference Revit API value/reference types rather than pure DTOs because Phase 3 needs stable `Reference` objects for `ReferenceArray`. This keeps the read-only engine Revit-aware but avoids holding mutable `Element` objects or modifying documents. The geometry service is deliberately document-free, so collectors remain responsible for API access, unsupported-case diagnostics, and source-specific reference extraction. The wall-axis projection model trades generality (any drawn line across many elements) for correctness and predictability (one selected wall, its openings, its end anchors) — this matches the real drafting intent and removes whole classes of false rejections. Wall-end anchors use geometry inspection because the Revit 2026 host-object utility surface does not provide end-face extraction. The min/max cap rule intentionally trusts the straight non-curtain wall solid topology: openings are interior cuts, physical end caps are extrema. The deprecated intersection helpers stay in the codebase as dead-but-tested utilities until the optional cross-cutting/grid path is either revived or removed. Chain-dimension readiness enforcement adds one extra pass over final candidates, which is negligible for MVP scope and eliminates a whole class of Phase 3 failure modes.

## PHILOSOPHY
Reference correctness and explainable diagnostics come before UI polish. Unsupported geometry should produce explicit diagnostics instead of silent omission or speculative heuristics. Choose the geometric model that matches the user's drafting intent (measure along a wall) over a more general model that produces structurally wrong candidate sets. Match units and vocabulary to the user's day-to-day workflow when presenting results.
