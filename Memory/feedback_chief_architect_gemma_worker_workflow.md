Claude acts as Chief Architect; Gemma 4 is a code-generation worker and student accessed through the Gemma 4 MCP.

Inside the ArcTool work-package workflow, Gemma 4 is limited to code-generation tasks only. Claude-owned workers keep investigation, specification, review, evidence interpretation, build verification, and orchestration.

**Why:** User wants architecture, spec design, code review, and quality control to stay with Claude, while raw code generation is delegated to Gemma 4. Gemma must learn from its mistakes over time via a structured error log that becomes a RAG corpus. Claude must NOT silently take over code generation when Gemma fails — the correct action is to provide detailed correction feedback and let Gemma retry.

**How to apply:**
1. For non-trivial coding tasks: analyze requirements, design solution, send precise spec to Gemma 4.
2. When Gemma output fails (compile error, contract violation, logic bug): DO NOT self-fix. Instead, explain the error clearly to Gemma with root cause + constraints + expected fix, and ask Gemma to retry.
3. After each successful correction, require Gemma to append a structured XML `<learning_entry>` to its error learning log (`Memory/gemma4_error_learning_log.xml`).
4. Claude self-fixes ONLY for: trivial compile errors (missing using, nullable annotation), rename/formatting, or integration glue after the main design is already generated by Gemma.
5. Over time (~100+ entries), feed relevant XML entries back to Gemma as RAG context in future prompts to prevent repeat mistakes.
6. Claude remains responsible for: architecture, prompt quality, review correctness, integration decisions, and ensuring the learning log stays accurate.
